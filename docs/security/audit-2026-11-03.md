# Security & correctness audit — 2026-11-03 (wave 2 modules)

**Scope:** `d6243c2`, the integration of the 14 wave-2 modules:
- money and stock: returns, offline order drafts, commissions, invoice write-off and print, imports
- access and security: MFA step-up, admin settings / employees / territories, workflow administration, audit row-image reader, CSV exports, security headers and CSP
- field and mobile: the Android shell (D-14 phase 2), email-code login, visit planning, performance indexes

**Method:** three independent reviewers, one per area (M money and stock, A access and security, F field and mobile), worked from the code alone. Each first ran `pnpm test:db` on the audited commit (2225 assertions, 0 failing files). DB findings were reproduced on PostgreSQL 16, the races with two concurrent sessions. The Android findings were read from the Capacitor 8.5.3 and plugin 1.3.1 sources; no device or emulator was available.

**Result:** 26 findings: 1 High, 7 Medium, 4 Low-Medium, 14 Low. Ten fix branches were merged on top of `87d6fac` (merge `0ba1acf`):
- every DB finding has a regression suite (46–53, plus suite 17) that was run red on the unfixed code first, except M-6, which was a coverage gap;
- the app findings have unit tests;
- the Android findings are Implemented; they are not yet built by the new CI workflow nor run on a phone.

Status words follow `docs/TESTING.md` §4. "Tested" here means the DB and unit tests pass on `0ba1acf` (2687 DB assertions, 1442 unit tests); nothing below has been clicked through on a live database, so nothing is Verified.

## Residual risks / not done

- **Returns (M-1):**
  - partial receipt is not supported; `receive_return` posts the whole return;
  - a received return cannot be cancelled. It stays at `received` if its invoice is written off (`INVALID_STATE`) or earlier goodwill credits or write-offs already cover the lines (`EXCEEDS_INVOICE_OPEN_AMOUNT`);
  - cash refunds for paid invoices remain an owner question; the credit stays as unapplied customer credit;
  - a return later than 90 days on a paid invoice, followed by a bounce of the remaining payment, leaves the rep the returned unit's commission (the normal no-clawback rule, compounded).
- **Imports (M-2):** opening stock has no DB backstop; it relies on the lock plus re-validation under READ COMMITTED (the PostgREST default).
- **MFA (A-M1, A-L2):**
  - `api.revoke_role` and `api.suspend_user` do not take `authz.lock_owner_set()` up front; the commit-time guards take it, which is enough for correctness;
  - `set_territory_coverage` is not gated (it routes new customers only);
  - anyone who later redefines `inventory.assert_quarantine_release`, `audit.read_row_images` or `api.decide_approval` must keep the `authz.require_mfa` call (suite 48 fails otherwise);
  - an export refused with `mfa_required` or `rate_limited` returns JSON with no prompt.
- **Exports (A-L4):** only `crm.customer.export` and `sales.order.export` exist; invoices, payments, aging, visits, stock and tracking exports have no dedicated export permission and are not MFA-gated (owner decision). `api.v_ar_aging` still returns `ledger_balance` to `finance.page.aging` holders; the export hides it only in the app. The `admin.security.types` labels for `export` and `export_result` are missing, so the security page shows the raw codes.
- **Settings (A-L3):** stored settings are not re-validated by the migration. `safeLogoUrl` in `src/modules/finance/print.ts` still accepts https URLs (the server now refuses them).
- **Workflow (A-L1):** `wf.put_stage` still accepts a fallback who does not hold the stage's permission or role; such a fallback is notified but cannot decide.
- **Android (F1, F3, F4, F8):**
  - on a WebView without `WEB_MESSAGE_LISTENER` and `DOCUMENT_START_SCRIPT` the app has no native features, and Capacitor's proxy path drops page headers and follows cross-host redirects (the custom HTTP client was not built);
  - script running in the deployment's own top frame can still call the three allowed plugin methods;
  - the pilot APK is signed with an unprotected SDK debug key, and each CI run makes a new key (uninstall the old APK first);
  - the pilot APK, the manifest grep and the badging check have not yet run in CI with the new workflow; Gradle has not built the Java here;
  - if the rep denies `POST_NOTIFICATIONS` on Android 13+, the location service runs with no visible notification;
  - no Dependabot entry for GitHub Actions.
- **Planning (F2, F6):** the `planned_by` backfill has no test (migrations run before the seed data). If the planner has no employee login any more, only a caller with global scope can cancel the visit.
- **Email codes (F7):** the hosted OTP length, expiry, template and rate limit are owner steps (`docs/runbooks/supabase-vercel-setup.md` §2); there is no app-side attempt counter.
- **Matcher (A-LM1):** Next matches case-sensitively, so a future public file with an upper-case extension would run through the proxy (the `public/` test would catch it).
- **Not run:** Playwright for any of the above, and no Android device test.
